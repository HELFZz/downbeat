Purpose: single source of truth for the visual style of an Android app
(Kotlin + Jetpack Compose). Based on reference screenshots of Google's
Material 3 Expressive (widgets, FAB menu, floating toolbar, wavy

Numeric values are close approximations, not an official dump.
If the user provides a screenshot that contradicts this file, the
screenshot wins.

!!! AGENT RULE #1 (COLORS) !!!
This file intentionally contains NO color values. The user will give a
palette in HEX codes (see section 2). Until the palette is provided:
  - DO NOT invent, guess or reuse default Material purple/lavender/pink.
  - Ask the user for the HEX codes.
  - Build all UI strictly through color ROLES (primary, surface,
    secondaryContainer, ...) so the palette can be dropped in later.
  - Never hardcode a HEX inside composables, only in the theme file.
The screenshots show lavender/pink/green/yellow colors: those are just
one example palette. IGNORE the hues in screenshots; copy only shapes,
layout, hierarchy, sizes, typography and motion.

---------------------------------------------------------------------
0. ONE-PARAGRAPH SUMMARY
---------------------------------------------------------------------
Material 3 Expressive = Material You base (tonal surfaces, color roles)
pushed much further: very round and VARIED shapes (pills, squircles,
scalloped "cookie" flowers), huge bold or quirky variable-font type,
big touch targets, strong contrast between the one important element
and everything else, wavy (sine) progress lines, shape-morphing buttons
and springy animations that overshoot slightly and settle. Depth comes
from tonal color containers, not shadows. Many different color roles are
used side by side on one screen (a pill in primaryContainer next to a
squircle in tertiaryContainer next to a card in surfaceContainer), so
the screen feels playful but still follows strict role logic.

---------------------------------------------------------------------
1. CORE PRINCIPLES (visible in the references)
---------------------------------------------------------------------
1. Big and bold: giant numerals (timers, temperature, balance), large
   emphasized titles, large pill buttons with generous padding.
2. Round everything: pills for actions and inputs, squircles
   (rounded squares) for FABs and tiles, big radii on cards/widgets.
3. Shape variety is the signature: pill + squircle + circle + scalloped
   cookie on the same screen. Do not make everything the same radius.
4. One dominant action per screen: biggest, most saturated container
   (e.g. wide "Pause" pill at the bottom). Secondary actions = tonal.
5. Tonal containers instead of shadows: separate areas by container
   color role, almost no elevation shadows.
6. Shape = state: pressed/selected elements change shape (pill <->
   squircle, circle <-> cookie). Animate the morph.
7. Wavy progress: active part of seek bars / progress is a moving sine
   wave; inactive part is a straight line ending with a small dot.
8. Motion is springy: position/size/shape overshoot a bit; color and
   alpha never overshoot.
9. Edge-to-edge, transparent system bars, content scrolls under.
10. Content dense but airy: 16-24dp margins, 8-12dp gaps between
    containers, rounded containers nested in rounded containers.

2.2 How roles are used (from the references; hue-independent)
  - Screen background = background/surface.
  - Big containers (cards, widgets, sheets) = surfaceContainer family.
    Higher importance/layer = higher container step.
  - Main big action (e.g. wide "Pause" pill, play button) = primary
    fill + onPrimary text/icon.
  - Soft pill buttons (Select, Add photos, Share album, Search in the
    FAB menu) = primaryContainer (or secondaryContainer) fill +
    onPrimaryContainer text/icon.
  - Accent squircle buttons (edit/pencil, add-friend, floating toolbar
    action) = tertiaryContainer fill + onTertiaryContainer icon.
  - Selected chip/toggle (e.g. "Going") = primary or secondary fill with
    check icon; unselected ("Not Going") = surfaceContainerLow/High,
    no border, rounded-rect shape.
  - Floating toolbar and nav-rail panels = lightest/darkest surface
    container, pill or large radius.
  - Close "X" circle of FAB menu = primary (dark, filled) with
    onPrimary icon.
  - Outlined pills ("Updated", "Tap to pay") = 2dp outline in
    primary/outline color + very light container fill + large label.
  - Progress: active = primary, inactive track = secondaryContainer or
    surfaceVariant, end dot = primary.
  - Widgets may each use a different role family (primary-container,
    secondary-container, tertiary-container, inverse) to look varied.
  - Text: onSurface for main, onSurfaceVariant for secondary.
  - Disabled: content 38% alpha, container 12% alpha.
  - State layers: hover 8%, focus 10%, pressed 10%, dragged 16% of the
    content color on top of the container.
  - Dynamic color (wallpaper-based) is OFF: use only the user palette.
  - Avoid decorative gradients and colored shadows.

3. SHAPE SYSTEM
---------------------------------------------------------------------
3.1 Corner radius scale
  none 0dp | extraSmall 4dp | small 8dp | medium 12dp | large 16dp |
  largeIncreased 20dp | extraLarge 28dp | extraLargeIncreased 32dp |
  extraExtraLarge 48dp | full = 50% (pill/circle)

3.2 Shape vocabulary seen in the references
  PILL            : action buttons, inputs, toolbars, nav indicator,
                    battery widget, "Updated"/"Tap to pay" outlined pills
  STADIUM-WIDE    : big weather/temperature widget (pill with one end
                    larger, ~48dp+ radius, organic)
  SQUIRCLE        : FAB (+), edit button, floating-toolbar action,
                    play button in media widget, "Add friend" extended
                    button, app tiles. Radius about 25-30% of side
                    (e.g. 56dp button -> 16-20dp; 96dp -> 28-32dp).
  CIRCLE          : close "X" button, avatars, side media buttons
  COOKIE/SCALLOP  : 8-12 lobed rounded flower. Used for clock face,
                    avatar placeholder, loader, leading icon in outlined
                    pills, "Breathing" progress ring. 1-2 per screen max.
  ROUNDED RECT    : unselected chips ("Not Going"): radius 12-16dp.
  LARGE CARD      : widgets, cards, sheets: 28-48dp radius, nested
                    elements inside use 16-24dp so corners look
                    concentric (inner radius = outer radius - padding).
  KEYPAD KEY      : pill (wide rounded) in 3x4 grid; the pressed key
                    changes shape/color.

3.3 Expressive shape library (MaterialShapes in Compose)
  Circle, Square, Slanted, Arch, Fan, Pill, Triangle, Diamond, ClamShell,
  Pentagon, Gem, Sunny, VerySunny, Cookie4/6/7/9/12, Clover4/8, Burst,
  SoftBurst, Boom, SoftBoom, Flower, Puffy, PuffyDiamond, Ghostish,
  PixelCircle, PixelTriangle, Bun, Heart, Oval.
  All can morph into each other (Morph / toShape()).

3.4 Shape morphing rules
  - Toggle/selected button: pill <-> squircle (shape changes with
    selection, color changes with it).
  - Pressed: squarer + scale 0.96-0.98.
  - Button group: neighbors of the pressed button get narrower.
  - FAB -> FAB menu: squircle morphs into a circle with "X" while the
    pills appear with stagger.
  - Play <-> Pause button: circle/squircle morph with icon crossfade.
  - Loader: continuously morphs between cookie/sunny/pill shapes.
  - Duration comes from spring tokens (section 8), ~300-500ms.

---------------------------------------------------------------------
4. TYPOGRAPHY
---------------------------------------------------------------------
Font: Google Sans Flex (Android 16 / Pixel), else Roboto Flex, else
Roboto. Variable axes are part of the style: weight, WIDTH and
ROUNDNESS. Expressive screens can also use a monospace/rounded display
font for hero numerals.

4.1 Baseline scale (size / line-height, weight, tracking)
  Display Large   57/64 w400 -0.25sp | Display Medium 45/52 w400
  Display Small   36/44 w400
  Headline L 32/40 | M 28/36 | S 24/32  (w400)
  Title L 22/28 w400 | M 16/24 w500 +0.15sp | S 14/20 w500 +0.1sp
  Body L 16/24 w400 +0.5sp | M 14/20 w400 +0.25sp | S 12/16 w400
  Label L 14/20 w500 | M 12/16 w500 | S 11/16 w500

4.2 Emphasized scale: same sizes, weight w600-700 (labels w700).
    Used for screen titles, selected states, primary buttons, big text.

4.3 Hero numerals (seen in references)
  - Timer "00 : 00 : 09" stacked vertically, ~96-120sp, monospaced
    look (slashed zero), light/regular weight, onSurface or primary.
  - Widget temperature "72°" ~72-96sp, bold, tight tracking, small
    degree sign raised.
  - Balance "$36.50" ~48-64sp, display-style numerals.
  - Battery "66" ~48sp bold inside pill.
  Use tabular (monospaced) figures for anything that counts/ticks.

4.4 Expressive text moments
  - Heading in rounded heavy style (ROND axis high, weight 800+) for
    friendly messages: "Now slowly exhale", "Hi there!", "Morning".
  - Wide (WDTH axis) text for titles in toolbars/headers when desired.
  - Buttons: Label Large/Title Medium emphasized, ~16-20sp for big
    pills ("Pause", "Tap to pay" go up to ~24sp for XL size).

4.5 Rules: max 2-3 styles per screen, sentence case, no ALL CAPS.
    Text color via roles only.

5. SPACING, LAYOUT, SIZES
---------------------------------------------------------------------
  Grid 4dp. Steps: 4, 8, 12, 16, 20, 24, 32, 48.
  Screen side margin: 16-24dp. Gap between sibling containers: 8-12dp,
  segmented lists 2-4dp.
  Touch targets >= 48dp; expressive prefers bigger.
    Button heights: XS 32 | S 40 | M 56 (default) | L 96 | XL 136
    Icon button container: 40-64dp
    FAB: 56 / 80 / 96dp squircle
    Navigation bar: 80dp (short 64dp)
    Search bar: 56dp pill
    Top app bar: small 64dp; medium flexible 112dp; large flexible 152dp
    Floating toolbar: 64dp pill
    Keypad key: ~72x56dp pill, 8dp gaps
    Media widget: 2 buttons ~64dp + center play squircle ~72-96dp
  Window classes: compact phone default; medium/expanded -> navigation
  rail 80dp (expanded rail 220-360dp with "Add friend" style extended
  squircle button on top and pill-shaped selected item).

8. MOTION
---------------------------------------------------------------------
8.1 Expressive spring tokens
  Spatial (position, size, shape, rotation; may overshoot)
    fast    stiffness 800   damping 0.6
    default stiffness 380   damping 0.8
    slow    stiffness 200   damping 0.8
  Effects (color, alpha; no overshoot)
    fast    stiffness 3800  damping 1.0
    default stiffness 1600  damping 1.0
    slow    stiffness 800   damping 1.0
  Calmer "standard" scheme for dense screens: spatial 700/0.9,
  effects 1600/1.0.
8.2 Rules
  - Springs, not fixed-duration tweens, for touch-driven motion.
  - fast = small elements (switch, chip, icon), default = buttons/
    cards/FAB, slow = full-screen containers.
  - Shared-axis / container transform between screens, predictive back
    with shrink + rounded corners.
  - Staggered list/menu entrance (30-50ms each, max ~8 items).
  - Press: scale 0.96-0.98 + shape morph + haptic.
  - Wavy progress: wave phase scrolls continuously while active;
    amplitude animates to 0 when paused/finished.
  - Respect system "Remove animations".

---------------------------------------------------------------------
9. ELEVATION
---------------------------------------------------------------------
  0dp surfaces; 1dp elevated cards; 3dp menus; 6dp FAB/floating
  toolbar; 12dp dialogs. Prefer color step over shadow. Shadows are
  soft neutral black, nearly invisible in dark theme. No tint overlays.

10. JETPACK COMPOSE NOTES
---------------------------------------------------------------------
  - androidx.compose.material3 1.4.0+ (Expressive APIs are
    @ExperimentalMaterial3ExpressiveApi; names may vary).
  - Define lightColorScheme/darkColorScheme ONLY from the user palette
    (section 2). No dynamicColorScheme.
  - MaterialExpressiveTheme(colorScheme, motionScheme =
    MotionScheme.expressive(), shapes, typography). Fallback:
    MaterialTheme + manual spring specs from section 8.
  - Components: LoadingIndicator / ContainedLoadingIndicator,
    LinearWavyProgressIndicator, CircularWavyProgressIndicator,
    ButtonGroup, ToggleButton, SplitButton, FloatingToolbar,
    FloatingActionButtonMenu, Large/MediumFlexibleTopAppBar,
    ShortNavigationBar, WideNavigationRail, ExpandedFullScreenSearchBar,
    MaterialShapes (+ toShape(), Morph), expressive Slider.
  - Fallback for missing components: Surface/Box with custom Shape
    (RoundedCornerShape, CircleShape, MaterialShapes) + animate*AsState
    with spring(dampingRatio, stiffness).
  - enableEdgeToEdge(); handle insets; system bar icon color by theme.
  - Variable font: use Google Sans Flex / Roboto Flex with
    FontVariation.Settings (weight, width, ROND) when supported.

11. DO / DON'T
---------------------------------------------------------------------
  DO   mix pill, squircle, circle and one cookie shape per screen
  DO   huge numerals and bold/rounded headings
  DO   one dominant primary action, others tonal
  DO   wavy progress for playback/download
  DO   springs + shape morph + haptics
  DO   use only user-provided palette via roles
  DON'T hardcode colors or invent a palette
  DON'T use sharp corners, hairline dividers everywhere, ALL CAPS
  DON'T use heavy shadows or gradients
  DON'T use touch targets < 48dp or text < 11sp
  DON'T put more than 1-2 decorative shapes on a screen
